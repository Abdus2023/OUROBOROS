# M1.16 — Crash-Safe External Checkpoint Publication

## Status

Normative design and implementation for external publication of the current trust-state-bound checkpoint.

## Purpose

A signed checkpoint is an authorization artifact. It must not be exposed as a partially written JSON document, and publication must not silently depend on repository-controlled state. M1.16 therefore separates **issuance** from **publication**:

```text
External genesis trust root
        ↓
Ordered journal replay
        ↓
Current TrustStore
        ↓
issue_current_checkpoint()
        ↓
Validated signed v2 checkpoint
        ↓
same-directory temporary file
        ↓
write + flush + fsync
        ↓
atomic replace
        ↓
parent-directory fsync
        ↓
Published current checkpoint
```

## Normative invariants

1. Publication accepts only a `TrustStateBoundCheckpoint`.
2. The checkpoint is structurally serialized before any target replacement.
3. The target's parent directory MUST already exist; publication MUST NOT create an authorization directory implicitly.
4. The temporary file MUST be created in the target's directory so that replacement remains an atomic same-filesystem operation.
5. Temporary creation MUST use exclusive creation and restrictive permissions.
6. Complete checkpoint bytes MUST be written and flushed before replacement.
7. The temporary file MUST be `fsync()`ed before replacement.
8. Replacement MUST use an atomic rename/replace operation.
9. The parent directory MUST be synchronized after replacement; failure is reported as a durability error rather than silently treated as success.
10. A pre-existing target symlink MUST be rejected.
11. Failed pre-replacement publication MUST remove its temporary file and MUST leave the previous target untouched.
12. Loading MUST read the complete file and validate it through the v2 checkpoint schema; empty, truncated, malformed, or schema-invalid files fail closed.
13. Publication MUST NOT append a journal event. An issuance event appended after signing would advance the journal head and immediately stale the checkpoint.
14. No private key material is accepted or stored by the publication layer.
15. Publication MUST NOT manufacture, reconstruct, or modify the trust root; issuance remains rooted in the external genesis trust store.

## Crash model

The critical ordering is:

```text
prepare temp
    → write all bytes
    → flush
    → fsync(temp)
    → atomic replace(target)
    → fsync(parent)
```

A crash before replacement leaves the previous target in place. A crash after replacement but before parent-directory synchronization is treated as a filesystem durability boundary: the process cannot claim durable publication until the directory synchronization succeeds.

The protocol intentionally does not attempt to provide transactional rollback after `os.replace()`. If directory synchronization fails after replacement, the caller receives a failure and must re-load/re-authenticate the resulting checkpoint rather than assuming the old target remains current.

## File permissions

The default publication mode is `0600`. Group/world-readable publication is rejected by the API. The checkpoint contains public authorization material and signatures, but restrictive permissions reduce accidental disclosure and prevent treating the artifact as ordinary shared repository data.

## Relationship to M1.15

M1.15 established **freshness**: a checkpoint is current only when its epoch, active signer, journal head, generation, and reconstructed trust-state digest all match the current external authorization boundary.

M1.16 establishes **publication integrity**: once such a checkpoint has been issued, its filesystem publication cannot expose a partially written artifact as the current checkpoint.

Together:

```text
Correct checkpoint
      +
Crash-safe publication
      =
Current authorization artifact
```

Neither layer replaces the other. Atomic publication cannot make an invalid or stale checkpoint authoritative, and a cryptographically valid checkpoint is insufficient if its publication can expose incomplete bytes.
