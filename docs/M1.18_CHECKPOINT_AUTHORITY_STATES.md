# M1.18 — Checkpoint Authority States

## Status

M1.18 defines an explicit vocabulary for checkpoint authority classification.

## Normative principle

A structurally valid signature is not sufficient for current authority. Current authority requires successful authentication against the externally provisioned genesis trust root, the complete ordered journal, the current journal head, the current repository generation, and the reconstructed trust-state digest.

## State vocabulary

| State | Meaning | May authorize current promotion? |
|---|---|---|
| `ABSENT` | No checkpoint artifact exists at the requested publication path. | No |
| `INVALID` | The artifact cannot be safely parsed/validated, or its trust history cannot be safely reconstructed. | No |
| `STALE` | The artifact is well-formed but no longer binds the current journal/generation/trust state. | No |
| `REVOKED` | The checkpoint signer is present in the authenticated trust history but is permanently revoked. | No |
| `CURRENT` | The checkpoint authenticates the current journal, generation, and reconstructed trust state under the external root. | Yes |

## Ordering of authority decisions

Classification is fail-closed:

```text
ABSENT / INVALID / STALE / REVOKED
                ↓
             DENY
                ↓
CURRENT only → authorize current use
```

`CURRENT` is not inferred from freshness metadata, filesystem timestamps, filenames, or repository-local declarations.

## Revocation semantics

A checkpoint signed by a key that has subsequently become `REVOKED` is never current authority. Revocation is stronger than ordinary staleness because it records an explicit authenticated loss of signing authority.

A revoked key cannot regain authority by modifying a checkpoint, trust-store file, repository file, or journal representation.

## Generation semantics

A generation mismatch prevents current authorization even when every other checkpoint field is structurally valid. A checkpoint from an earlier repository generation is therefore classified as non-current.

## Promotion boundary

Callers requiring authorization MUST use `require_current_checkpoint()`. No caller may treat `INVALID`, `STALE`, `REVOKED`, or `ABSENT` as an alternate success state.

## Security invariant

> **Checkpoint classification describes authority; it never creates authority.**

The external genesis trust root remains outside repository-controlled state.
