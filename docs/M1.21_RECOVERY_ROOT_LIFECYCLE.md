# M1.21 — Recovery-Root Lifecycle

## Status

Normative M1.21 specification.

## Purpose

M1.20 introduced an externally provisioned emergency recovery root so a compromised ACTIVE trust key can be replaced without allowing the repository to manufacture a new authority. M1.21 gives that recovery root an authenticated lifecycle.

The repository may record recovery-root transitions, but it may not originate the first recovery root. The initial recovery root remains an external provisioning input.

## Model

```text
External Recovery Root (epoch n)
            |
            | signed root-rotation statement
            v
Journaled Recovery-Root Transition
            |
            v
Current Recovery Root (epoch n+1)
            |
            v
Emergency Trust Replacement
```

## Invariants

1. **External genesis** — the initial recovery root MUST be supplied outside repository-controlled state.
2. **Exact epoch continuity** — a root rotation MUST have `to_epoch = from_epoch + 1`.
3. **Current signer only** — a root rotation MUST be signed by the currently provisioned/reconstructed recovery root.
4. **Fresh replacement** — replacement key ID and public key MUST differ from the current root.
5. **Ordered replay** — recovery-root transitions are interpreted strictly in journal order.
6. **Replay resistance** — a transition binding digest MUST NOT be applied twice.
7. **Fail closed without root** — a journal containing recovery-root transitions cannot be reconstructed without the externally provisioned genesis recovery root.
8. **No run authority** — recovery-root transitions MUST NOT carry run, action, or repository-generation scope.
9. **Private-key exclusion** — recovery-root records contain public material and signatures only; private key material MUST remain external.
10. **No repository bootstrap of root** — a repository-local file, event, checkpoint, timestamp, filename, or generated key MUST NOT establish the initial recovery root.

## Consequences

After a successful rotation, signatures from the previous recovery root cannot authorize later emergency operations because replay resolves the current recovery authority before authenticating each subsequent statement. The old root remains useful only for historical verification of the rotation that replaced it.

A compromised current recovery root is intentionally **not** recoverable through repository-local state. That is the next break-glass boundary: an independent externally provisioned recovery-of-recovery mechanism is required rather than silently weakening this invariant.

## Authority rule

> Recovery-root rotation changes which external emergency authority is current; it never creates the root of trust from repository data.

## Currentness

The recovery-root epoch is an external-authority lifecycle counter. It is distinct from the normal trust-store epoch. A recovery-root rotation therefore does not itself change the normal trust epoch. Only a signed emergency replacement changes the normal trust state.
