# M1.22 — Recovery-of-Recovery Authority

## Status

M1.22 defines the break-glass boundary for the case where the current emergency recovery root is itself compromised.

The repository cannot repair a compromised recovery root by choosing a new key from repository-local state. Instead, an **independent externally provisioned quorum authority** is required.

## Authority model

```text
Independent Recovery-of-Recovery Root
        │
        │  N-of-M signatures
        ▼
Recovery-of-Recovery Statement
        │
        ├── expected recovery-root key id
        ├── expected recovery-root epoch
        ├── replacement recovery-root key
        ├── authority epoch
        └── quorum signatures
        │
        ▼
Authenticated Recovery-Root Replacement
        │
        ▼
New Emergency Recovery Authority
```

The quorum is deliberately separate from the ordinary trust key and from the emergency recovery root. Its private signing keys are external and are never serialized into the repository.

## Normative invariants

1. The recovery-of-recovery authority MUST be externally provisioned.
2. Its public key set and threshold MUST NOT be inferred from repository files, journal records, checkpoints, timestamps, or generation metadata.
3. A statement MUST name the exact current recovery-root key identifier and epoch it replaces.
4. The statement MUST bind the replacement recovery-root key material and reason cryptographically.
5. At least `threshold` distinct authorized quorum signatures MUST verify over the same canonical statement.
6. Duplicate signers MUST be rejected.
7. Unknown or unauthorized signers MUST be rejected.
8. The quorum authority epoch MUST match the externally provisioned epoch.
9. A replacement recovery-root key identifier and public key MUST differ from the current root.
10. A break-glass statement MUST be durable before it can affect recovered authority.
11. Break-glass events MUST NOT be run-scoped, action-scoped, or generation-scoped.
12. Replaying the same statement MUST fail closed.
13. Historical recovery-root authority MUST NOT regain authority after break-glass replacement.
14. If the external quorum authority is absent, recovery MUST fail closed.
15. The new recovery root inherits the next recovery-root epoch exactly once.
16. Recovery-of-recovery does not itself change the normal trust-store epoch.
17. No private key, seed, or signing secret may appear in a serialized statement or event.

## Why a quorum

M1.21 already prevents the repository from replacing the recovery root autonomously, but a single emergency root remains a single cryptographic failure domain. M1.22 introduces separation of control: recovery of that root requires multiple independently held recovery-of-recovery signers.

The quorum itself is an external root in M1.22. Its own lifecycle is intentionally not delegated to the repository. Any future rotation or governance of the quorum must introduce an additional authenticated policy boundary rather than silently weakening this one.

## Replay and rollback resistance

A statement carries the expected recovery-root identifier and epoch. The journal replay starts from the externally provisioned recovery root and applies operations in order. Once a break-glass replacement is accepted, later operations must use the replacement root. Reusing an earlier recovery-root identifier is rejected by the lifecycle replay rules.

The repository therefore cannot obtain authority by:

- editing a checkpoint;
- editing the trust store;
- deleting a recovery event;
- changing file timestamps;
- changing repository generation metadata;
- replaying an old break-glass statement; or
- selecting a preferred cached key.

## Failure semantics

```text
No quorum root                 → FAIL CLOSED
Insufficient signatures        → FAIL CLOSED
Unknown signer                 → FAIL CLOSED
Duplicate signer               → FAIL CLOSED
Wrong recovery-root identity   → FAIL CLOSED
Wrong recovery-root epoch      → FAIL CLOSED
Invalid signature              → FAIL CLOSED
Replayed statement             → FAIL CLOSED
Fresh valid quorum statement   → replace root
```

## Remaining boundary

M1.22 does not claim that the recovery-of-recovery quorum is magically immutable. It establishes it as an **independent external root**. Compromise of that quorum remains an operational governance problem requiring a separately authenticated provisioning/rotation process. The key architectural property is preserved: repository-local state can never manufacture its own final recovery authority.
