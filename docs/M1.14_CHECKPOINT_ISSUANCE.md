# M1.14 — Authenticated Checkpoint Issuance

## Status

M1.14 defines checkpoint issuance as an authenticated operation over the externally rooted current trust state.

## Normative contract

A current checkpoint MAY be issued only when all of the following hold:

1. The journal is fully integrity-validated.
2. The trust state is reconstructed from the externally provisioned genesis store plus the ordered authenticated trust-transition events.
3. The signing key is the unique current `ACTIVE` trust key.
4. The supplied private key cryptographically matches that active public key.
5. The checkpoint generation is explicitly supplied and non-empty.
6. The checkpoint binds the exact current journal head sequence and digest.
7. The checkpoint trust epoch equals the reconstructed trust-store epoch.
8. The checkpoint binds the canonical digest of the reconstructed trust state.

The repository cannot select, manufacture, or replace the external genesis root.

## API

`issue_current_checkpoint(journal, initial_store, private_key, key_id, generation=...)`

The issuance helper reconstructs trust state itself. Callers cannot provide an arbitrary trust store and obtain a current checkpoint from it.

The operation intentionally does **not** append an issuance event to the same journal. A post-signing journal append would change the head and make the checkpoint stale immediately. The signed checkpoint is the durable authorization artifact; its placement is external to the mutable journal.

## Failure behavior

Issuance fails closed for:

- empty journals;
- malformed or tampered journal records;
- invalid trust-transition history;
- non-active signing keys;
- mismatched private/public key material;
- missing generation;
- invalid trust-store reconstruction.

## Security property

The issuance path is:

```text
EXTERNAL GENESIS ROOT
        |
        v
VALIDATED JOURNAL
        |
        v
AUTHENTICATED TRUST REPLAY
        |
        v
CURRENT CANONICAL TRUST STATE
        |
        +---- active signer identity
        |
        +---- current journal head
        |
        +---- current generation
        |
        +---- trust-state digest
        |
        v
SIGNED v2 CHECKPOINT
```

Thus checkpoint production cannot be performed against a stale, repository-invented, or independently supplied trust state while still being presented as a current authoritative checkpoint.
